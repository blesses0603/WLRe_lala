# WLRe:LaLa | v0.5.6 開發版

> **版本狀態（2026-10-20）**：本頁整理 v0.5.6 開發中的功能與更新，**不代表已發布 v0.5.6 安裝包**；程式版本來源 `wlre/__init__.py` 現為 **0.5.6**，正式已發布的版本是 [**v0.5.0（2026-10-17）**](https://github.com/blesses0603/WLRe_lala/releases/tag/v0.5.0)；遊戲資料／協定核對基準為 **1262**。**v0.6.0 預定下一次正式 Release，尚未建立標籤或新版安裝包。**

**WLRe:LaLa** 是《飄流幻境 RE：星之方舟》的 Python 桌面客戶端工具，使用 Tkinter／ttk、遊戲封包與內建資源。桌面版獨立維護，Android 不在本倉庫的建置範圍內。

## v0.5.6 更新重點

> **2026-10-20 health-25804 戰鬥與戰後診斷修復**：安全記錄 S51-1 異常的戰鬥類型／場次、區分同一分鐘內不同場的自動戰鬥狀態、記錄手動／斷線／維護不確定等 AI 停止來源；戰後修理／整理以白名單狀態和每 10 秒的等待秒數追蹤 pending／uncertain。保留異常 S51-1 整包捨棄、逐筆確認、不盲目重送、不自行開啟下一場等原有安全保護。**未知 S51-1 變體尚未取得可靠協定證據，不推測解碼、不宣稱根因已修復。**

本版為 **v0.5.6 開發中 Bug 修復版**；本次不建立 Tag 或觸發 Nuitka。下一次正式 Release 仍規劃 v0.6.0。

## v0.5.5 更新重點

> **協力戰鬥結束後接續卡住修復**：依官方 1262 `FightManager.FightOver` 和 `CooperateEventManger.CheckFightCount` 校正。若尚未收到 `S186-15`，不再永久停在「cooperative_wait」；戰鬥退場後使用官方預設 2.5 秒等待，再送一次原有 `C20-6 00` 事件接續。若已確認剩餘場次且本機勝利，保留官方 5 秒等待分支。**只接續伺服器事件，不自行開始下一場、不重送未確認封包、不推定通關或領獎**。

> **AI 待命不再鎖住其他功能**：移除因 `auto_battle.enabled` 為真就拒絕創房／入房／離房、配點、夥伴出戰與開始製作的多餘限制。仍在實際戰鬥、事件、戰後待回覆、移動或交易操作未確認時保持各功能原有安全鎖。AI 仍需本機手動開啟，實際戰鬥每回合保持單位去重。

> **戰後安全診斷**：健康 Log 新增去識別化的 `post_battle phase=scheduled/sent/completed` 及 2.5／5 秒接續依據，不記角色、密碼、封包內容、實際獎勵或對手身分。[診斷說明](docs/CONNECTION_DIAGNOSTICS.md)

本版為 **v0.5.5 開發中 Bug 修復版**；不建立 Tag、不啟動 Nuitka，下一次正式 Release 仍規劃 v0.6.0。

## v0.5.4 更新重點

> **協力自動戰鬥修正（待正式服驗收）**：依官方 1262 `AutoPlay.AutoFight` 確認協力事件戰鬥 `WarStyle=16` 並非禁止自動戰鬥，修正 LaLa 的額外暫停限制。仍僅在已確認開啟戰鬥、收到有效回合與本角色出戰單位、使用者已啟用 AI 時下令，每回合保留防重送。原有幽冥突襲 21、星穹試煉 23、群星巔峰 24 限制不變；不自行配對、切換夥伴或啟用 AI。

> **戰鬥 AI 狀態可觀測性**：主頁顯示實際 AI 待命、暫停、等待、受阻或下令狀態，不再只顯示「戰鬥中」。健康 Log 增加去識別化的 `auto_battle` 狀態、`war_style`、回合與本機存活可下令單位數，方便辨別一般副本的回合未同步等情況，不記角色名稱／動作內容。[診斷詳情](docs/CONNECTION_DIAGNOSTICS.md)

**v0.5.4 僅為開發中的 Bug 修復版本**，不建立 Git Tag，不啟動 Nuitka 正式打包；仍以 v0.6.0 為下一次正式 Release。

## v0.5.3 更新重點

> **副本／協力人數提示優化**：獨立視窗中增加伺服器同步的房間人數說明。一般副本顯示「目前 2/6 人，尚缺 4 人（上限 12 人）」，依官方最低人數判斷；協力顯示「目前 1/2 人，尚缺 1 人（協力須滿員）」，以房間設定容量判斷。到齊後才顯示「已達最低人數／已滿員」，房主是否真正可以開始仍須符合原有房主身分、名單同步及操作安全條件；**人數足夠不會自動發送開始封包**。 [副本說明](docs/INSTANCES.md)


> **v0.5.2 獨立視窗**：除主頁外，「組隊、夥伴出戰、遠征、副本、煉金、製作、經驗效率」皆由主頁入口開啟獨立固定視窗；所有視窗開啟時依**主視窗中心**定位，按右上角關閉只隱藏，不清除操作狀態；主畫面地圖、事件紀錄、聊天及戰場保留原來的即時監看。

> **副本／協力官方圖示**：已加入原始遊戲 PNG 的自動載入支援（`wlre/resources/assets/instance-menu/Menu_Dungeon.png`、`Menu_Cooperate.png`）。這兩張**截圖右側原始貼圖尚未在現有資源中確認**，未取得前安全地顯示文字，不使用擷取截圖或猜造貼圖。來源與提取清單見 [圖示說明](wlre/resources/assets/instance-menu/SOURCE.md)。


**CI 建置規則（2026-10-19）**：Draft PR 與一般提交只自動跑 Windows／Linux／macOS 測試，**不自動編譯 EXE／APP**。需要提前實機驗證時可從 GitHub Actions 手動執行原生打包；正式標籤 `vX.Y.Z` 仍透過發版流程自動建置。詳細規則請見 [Nuitka 建置文件](docs/NUITKA_BUILD.md)。

以下以**v0.5.3 開發版**整合先前 v0.5.1～v0.5.2 功能（包含副本／協力 PR #23）；各項仍以正式伺服器驗收結果為準。完成功能程式碼並不等於已通過正式伺服器端到端驗證。

### 新增功能

- **官方 1262 繁體中文副本清單（PR #23）**：自實際 `DungeonData_C`、`ScenesData_C`、`CooperateEventData_C` 與 `TextData_C` 匯入 30 筆設定／24 個副本 ID（27 筆主要、3 筆協力），保留難度版本、等級、隊伍人數、時間與 178 筆非空獎勵欄位。副本名稱與房間即時清單分開顯示，協力事件採活動專屬官方名稱；此資料不代表伺服器目前開放房間。[建置紀錄](docs/INSTANCES.md)

- **副本完成／協力免費領獎（PR #23 第 07 項，待實服驗收）**：一般與新式副本僅由 S85-15／S85-21-100 判定完成；協力以 S186-11 勝場與寶箱狀態為準。新增 S186-10 最多四筆官方獎品資料解碼、C186-10 免費領獎、C186-21 主動放棄，免費獎勵自動領取預設關閉，須明確開啟；包包空位不足、狀態不明或付款型寶箱時不會自動領獎／扣點／重送。協力連戰處理沿用 S186-15 場次與戰後事件 C20-6，正常出戰夥伴不受影響。[第 07 項說明](docs/INSTANCES.md)
- **副本入場與協力戰鬥銜接（PR #23 第 06 項，待實服驗收）**：依官方 1262 一般副本 `C85-9` 空內容封包，於房間已收到 `S85-5 kind=3` 後，玩家手動二次確認進入；以本角色 `S7-1／S12-1` 實際場景核對入場，45 秒結果不明不自動重送。協力沿用 `C186-7` 配對，接收 `S186-2 code 17／18` 配對通知與既有 `S11` 戰鬥封包，不另發起始封包，不更換夥伴，也不把戰鬥勝負當成領獎成功。[第 06 項說明](docs/INSTANCES.md)
- **一般副本房主開始挑戰（PR #23 第 05 項，待實服驗收）**：對照官方 1262 `Dungeon.SendStartDungeon` 與 `UICheckPlayerList.OnClick_Event_Confirm`，僅由房主、人數達 `minDup` 且 S85-4 成員清單完整時手動送出空內容的 `C85-7`。以 `S85-5 kind=3` 確認開始，20 秒未回覆不重送。協力副本啟動仍沿用第 04 項的房主 `C186-7` 準備／配對，不另送起始封包，角色出戰夥伴保持不變。[第 05 項說明](docs/INSTANCES.md)
- **協力準備／取消準備（PR #23 第 04 項，待實服驗收）**：沿用玩家平常出戰的夥伴，不新增選擇夥伴、變更出戰或休息封包。依官方 C186-7 `roomId:u16 + standby:u8`，僅房主且房間成員已滿時手動切換；以 S186-3 核實，S186-20 為資訊通知而非單獨成功確認。20 秒逾時不重送，現場可能直接進入配對／挑戰，送出前會再次確認。[協力準備規則](docs/INSTANCES.md)
- **副本加入／離開房間（PR #23 第 03 項，待實服驗收）**：依最新伺服器清單挑選一般／協力房間，私人房間需輸入密碼；一般使用 C85-5／C85-6 並由 S85-3、S85-5／S85-12 確認，協力使用 C186-4／C186-5 並由 S186-2、S186-3、S186-13 確認。加入前要求清單 120 秒內更新、協力票券／點數確認；加入／離開 20 秒逾時視為結果不明，不自動重送。只有伺服器通知才更新房間狀態，正式服仍待驗收。[副本加入與離房流程](docs/INSTANCES.md)
- **副本建立公開／私人房間（PR #23 第 02 項，待實服驗收）**：依官方 C85-3 與 C186-1 提供建立對話框、公開／私人設定、四位密碼、協力人數、可能扣點確認，送出後由 S85-2／S85-5 或 S186-2／S186-3 確認房間狀態。保護重複發送與 20 秒逾時，結果不明時必須重新登入同步。官方協力活動資料顯示無指定夥伴獎勵限制；本功能尚未以正式遊戲伺服器驗收。[副本創房說明](docs/INSTANCES.md)
- **副本房間唯讀同步（Phase 03～04）**：支援手動取得 C85-1／C186-17 房間清單、解析 S85／S186 已核對的房間／成員／狀態／獎勵通知，分別顯示在「主要／協力」頁面。目前已追加手動開始／入場及免費領獎（均仍待正式伺服器驗收）。[進度與限制](docs/INSTANCES.md)
- **副本系統後續建構（Phase 02）**：依 1262 `DungeonData`、`CooperateEventData`、`ScenesData_C`（`StageData:New`） 與 `AwardData` Lua 格式加入嚴格的官方二進位資料解析器，支援 16 格獎勵、指定夥伴、地圖與進入條件；尚未取得相對應的二進位表時不產生虛構副本名稱。此模組不自動掃描、修改遊戲目錄。[副本建置進度](docs/INSTANCES.md)

- **副本／協力副本入口（建構階段）**：主介面增加「副本」分頁，內含「主要」與「協力」次分頁，分別預留副本清單、進入條件與狀態欄位。未接入經驗證的 1262 副本資料及進入協定前不填入假資料，進入按鈕保持停用；本次不新增副本封包、自動進入或隊伍操作。[介面配置](docs/UI_LAYOUT.md)
- **遠征自動化**：新增遠征分頁及主頁控制，內建官方 1262 版 **260 筆繁體中文任務名稱、任務資料與 10 級遠征資料**，顯示減免後耗時、預估成功率與任務獎勵（機率獎勵另行標示）。支援時間、成功率、好友度門檻與恢復物品設定；從閒置夥伴中搜尋合適隊伍，逐隊派遣、領獎並等待伺服器確認。設定依帳號＋伺服器保存，登入不會自行啟動遠征。[遠征說明](docs/EXPEDITION.md)
- **夥伴出戰與休息**：新增夥伴分頁，顯示等級、HP／SP、忠誠與能力；非戰鬥時可要求出戰或休息，實際狀態待伺服器確認。
- **角色五項能力配點**：新增能力配點視窗，依官方協定比對可用點數、原始數值與伺服器回覆；戰鬥中禁止送出，待確認時不能重複提交。[配點規則](docs/attribute_points_1262.md)
- **圖示背包與超空間袋**：一般背包調整為 **6×4 圖示格**、物品詳情與分頁。超空間袋顯示經核對的 S62 儲藏室／雜物櫃資料；**目前只支援已同步內容的唯讀檢視**，未收到初始資料不顯示假庫存，也不支援存入、領出或自動取料。[倉儲核對](docs/room_storage_1262.md)
- **戰後修理／物品整理**：自動戰鬥設定加入「修理／整理」，提供修理道具優先序、剩餘耐久門檻、十五格指定整理名單。只從可靠同步的背包選物，逐筆等待扣料／效果確認，逾時不盲目重送；預設停用。[戰後維護](docs/MAINTENANCE.md)

### 介面更新與修正

- 主頁改為**三欄功能卡**與精簡自動化狀態，加入遠征入口；維持 1280×800 主視窗、固定小地圖及聊天／戰場資訊區。
- 採用遊戲原版**圓形功能入口、按鈕與設定／背包／回復圖示**；統一操作樣式、視窗控制及背景襯底。
- **主頁四個快捷入口換用原版 PNG**：經驗效率（`MainIcon_020`）、隊伍檢查（`MainIcon_005`）、煉金（`MainIcon_007`）、製作（`MainIcon_011`）的文字「開啟」按鈕改用遊戲 1262 原始透明圖示；分頁切換和現有指令不變，無需外部素材或設定搬移。
- **共用視窗與背景架構**：固定 1280×800 插畫座標系、父容器裁切、對話框置中與自訂標題列外框，減少背景錯位、黑色條帶及重複青框；HiDPI 動態縮放仍待完善。
- 調整背包格位、超空間袋的頁籤與裁切邊界，並改善緊湊補給、製作及經驗效率版面。
- 製作保留分類、搜尋、收藏、圖示列表（每頁 12 項）、配方詳情及佇列；組隊清單移除不必要的捲動條而保留原操作。
- 修正未確認加入公會時的聊天發送判斷及發話鎖定復原，降低操作卡住的風險。
- 沿用原生下拉選單焦點錯誤恢復、最近伺服器回應／連線待確認診斷，以及有界顯示佇列、座標快取、每兩小時清理過期顯示資料。[連線診斷](docs/CONNECTION_DIAGNOSTICS.md)
- **跨日連線異常診斷強化**：針對 `client_error` 增加安全的 `connection_exception`、`worker_exception` 紀錄，標記例外類型與程式位置但不收集密碼、封包、例外訊息或絕對路徑；保留原本 Log 目錄與輪替政策，暫不改動連線／重連及副本行為。[診斷內容](docs/CONNECTION_DIAGNOSTICS.md)
- **遠征領獎後任務表更新修正**：S31-19 按官方 1262 Lua 讀取完整任務表與末尾 Boolean，避免多餘尾端資料觸發用戶端斷線；新增封包數值 ID／處理階段的隱私安全診斷與模擬領獎回歸測試。[遠征協定](docs/EXPEDITION.md)
- **遠征出發回覆修正**：依 1262 官方 `RevExpeditionStart` 行為，S31-15 允許未解讀的回覆本文並僅記錄位元組數，避免被嚴格結尾檢查誤判造成斷線；其他遠征封包仍須完整驗證，另有空／非空本文及連線回歸測試。[遠征說明](docs/EXPEDITION.md)
- **S51-1 戰鬥屬性容錯及診斷**：依官方 1262 每筆 7 bytes 佈局；遇不完整封包整包略過，不更新 HP／SP、不讓單一異常 S51-1 使連線中止。診斷只記封包數值 ID、長度與剩餘筆數，不收集封包本文，其他協定仍嚴格驗證。[連線診斷](docs/CONNECTION_DIAGNOSTICS.md)

### 架構拆分與相容性

- **遠征服務**：將派遣管理、官方資料、隊伍搜尋拆分，維持 `wlre.services.expedition` 舊匯入相容。
- **遠征介面**：拆為主面板、設定、任務、夥伴與詳情等獨立視圖，保留原介面呼叫方式。
- **自動戰鬥規則**：抽出 AI 草稿模型、行動編輯器及規則卡片，既有設定入口仍可使用。
- **製作介面與主題**：圖示快取、清單、配方、佇列分模組；分離玻璃背景繪製與 ttk 樣式，精簡網路客戶端過時匯入。
- **安全協調**：明確化介面／連線工作執行緒邊界、角色狀態與物品保留權責；多種自動流程共用背包時，避免尚待伺服器確認的物品被重複使用。

## 啟動與建置

| 平台 | 原始碼啟動 | 成品／建置 |
| --- | --- | --- |
| Windows | `run_client.bat`，或 `python -m wlre.launcher` | 執行 `build_nuitka.bat`，預設建立 `WLRe_LaLa.dist` 資料夾版 |
| macOS | `run_client.command`（需可用的 Python 與 Tk） | 發版流程支援 Apple Silicon／Intel 原生 Nuitka App；以實際發布產物為準 |
| Linux | `python -m wlre.launcher`（需 Tk 顯示環境） | 供原始碼開發／測試；目前不宣稱提供 Linux 正式安裝包 |

原始碼相關依賴請參閱 `requirements-ui.txt`，Windows Nuitka 細節請見 [建置說明](docs/NUITKA_BUILD.md)。

**更新成品**：先關閉舊版；若 Releases 已提供新版，請下載對應平台的完整壓縮檔，**解壓至新資料夾**後再執行 Windows `WLRe_LaLa.exe` 或 macOS App。資料夾版不可只複製 EXE，也不建議覆蓋舊版執行目錄。

## 使用限制

- 遠征可與自動戰鬥、徘徊同時啟用，但實際操作仍受戰鬥、活動及共用物品的待確認狀態限制，**並非所有指令可平行送出**。
- 設定依帳號／伺服器保存；載入設定**不會自動啟動** AI 或遠征。Windows 的登入密碼保護依 DPAPI，不能假設其他平台有相同能力。
- 指令「送出」不等於成功；相關功能依伺服器成功回覆、扣料及數值同步確認。操作逾時或狀態不明時不盲目重送，必要時重新登入同步。
- 遠征派遣與領獎、戰後修理／販售／丟棄、角色配點及超空間袋同步仍需真實伺服器端到端確認；請勿把本機合成測試視作已通過實服驗證。

## 測試與驗證

```bash
python -m unittest discover -s tests -q
python WLRE_Client.py --self-test
python WLRE_Client.py --smoke-test-gui
python -m tools.build.build_nuitka --dry-run
```

`--self-test` 檢查必要資源，`--smoke-test-gui` 建立視窗但不登入；GUI 測試需要顯示環境（Linux CI 使用 Xvfb）。`.github/workflows/test.yml` 現在於一般 PR／main 提交自動執行 **Linux、Windows、macOS** 完整回歸；需要安裝包進行人工驗收時，可在 GitHub Actions 手動執行 `.github/workflows/desktop-packaging.yml`，編譯 Windows x64 EXE、macOS Apple Silicon／Intel 原生建置；一般 PR／main 不會自動執行這項昂貴建置。正式版本標籤仍由發版流程執行原生打包。實際是否通過以 GitHub Actions 最新結果為準。[驗證紀錄](docs/VALIDATION.md) · [第 10 項稽核](docs/PHASE10_AUDIT.md)
