- **製作介面與主題**：圖示快取、清單、配方、佇列分模組；分離玻璃背景繪製與 ttk 樣式，精簡網路客戶端過時匯入。
- **安全協調**：明確化介面／連線工作執行緒邊界、角色狀態與物品保留權責；多種自動流程共用背包時，避免尚待伺服器確認的物品被重複使用。

## 啟動與建置

| 平台 | 原始碼啟動 | 成品／建置 |
| --- | --- | --- |
| Windows | `run_client.bat`，或 `python -m wlre.launcher` | 執行 `build_nuitka.bat`，預設建立 `WLRe_LaLa.dist` 資料夾版 |
| macOS | `run_client.command`（需可用的 Python 與 Tk） | 發版流程支援 Apple Silicon／Intel 原生 Nuitka App；以實際發布產物為準 |
| Linux | `python -m wlre.launcher`（需 Tk 顯示環境） | 供原始碼開發／測試；目前不宣稱提供 Linux 正式安裝包 |

原始碼相關依賴請參閱 `requirements-ui.txt`，Windows Nuitka 細節請見 [建置說明](docs/NUITKA_BUILD.md)。

> **UnityFS 解包器（PR #56，v0.6.1 開發候選）**：原生 Windows／macOS 建置流程已加入 `requirements-extractor.txt`（固定 UnityPy 版本），預計隨 EXE／APP 一併封裝，使用者不需另外安裝 Python/UnityPy。新建置自檢 `--self-test-unityfs` 會核對內建模組及 LZ4／Brotli。**正式打包產物與真實官方 Bundle 解包仍須分別驗收**；此功能尚未隨目前 main 或既有 Release 發布。

> **Launcher 自動資源候選（同一 Draft PR）**：LaLa 的原始碼版啟動器及 Nuitka 正式入口共用資源準備服務，**先顯示 Launcher 資源準備進度視窗，再開啟主程式**，並讀取官方版本與兩包 Manifest，依精確 AssetPath 下載／校驗必要 Bundle、解包並把新版候選資料存入個人快取；**不需自行建立 bindings.json**。登入前版本視窗僅顯示 Launcher 的唯讀狀態，不會再次下載。沒有網路、官方更動未知格式或超過下載額度時安全停止。新生成的 SHA 僅作完整性校驗，不代表正式版本已核准，未知新版仍不會自動解除登入封鎖。Launcher 會以真實事件顯示 Manifest 驗證、必要 Bundle 完成筆數、四類資料解包及候選快取狀態，不顯示猜測百分比。開發者也可使用 `python -m tools.plan_official_catalog --download --parse` 單獨執行；正式 EXE 仍需打包與真實 Bundle 驗收。

**更新成品**：先關閉舊版；若 Releases 已提供新版，請下載對應平台的完整壓縮檔，**解壓至新資料夾**後再執行 Windows `WLRe_LaLa.exe` 或 macOS App。資料夾版不可只複製 EXE，也不建議覆蓋舊版執行目錄。

## 使用限制

- 遠征可與自動戰鬥、徘徊同時啟用，但實際操作仍受戰鬥、活動及共用物品的待確認狀態限制，**並非所有指令可平行送出**。
- 設定依帳號／伺服器保存；載入設定**不會自動啟動** AI 或遠征。Windows 的登入密碼保護依 DPAPI，不能假設其他平台有相同能力。
- 指令「送出」不等於成功；相關功能依伺服器成功回覆、扣料及數值同步確認。操作逾時或狀態不明時不盲目重送，必要時重新登入同步。
- 遠征派遣與領獎、戰後修理／販售／丟棄、角色配點及超空間袋同步仍需真實伺服器端到端確認；請勿把本機合成測試視作已通過實服驗證。

## 測試與驗證

```bash
python -m unittest discover -s tests -q
python WLRE_Client.py --self-test
python WLRE_Client.py --smoke-test-gui
python -m tools.build.build_nuitka --dry-run
```

`--self-test` 檢查必要資源，`--smoke-test-gui` 建立視窗但不登入；GUI 測試需要顯示環境（Linux CI 使用 Xvfb）。`.github/workflows/test.yml` 現在於一般 PR／main 提交自動執行 **Linux、Windows、macOS** 完整回歸；需要安裝包進行人工驗收時，可在 GitHub Actions 手動執行 `.github/workflows/desktop-packaging.yml`，編譯 Windows x64 EXE、macOS Apple Silicon／Intel 原生建置；一般 PR／main 不會自動執行這項昂貴建置。正式版本標籤仍由發版流程執行原生打包。實際是否通過以 GitHub Actions 最新結果為準。[驗證紀錄](docs/VALIDATION.md) · [第 10 項稽核](docs/PHASE10_AUDIT.md)
