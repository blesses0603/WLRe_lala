# 動態配方排程接線

## 原因與修正

清單瀏覽已恢復，但 parse_runtime_recipes 與 activate_dynamic_recipes 仍把所有配方強制設為 read_only，導致「加入排程」與自訂清單均被擋住。現保留原始限時標記，一般配方交由現有開放狀態、圖紙、活動限制、設備、背包與排程狀態檢查決定可用性。

正式服務原本未接上 crafting_official_v1286。現在依當次 Smith 解析出的配方識別欄位選擇格式，不固定判斷官方版本號：
- 35-byte 配方以 recipe_id 與 item_id 組裝 C64-1。
- S64-1／S64-16 以完整當次配方目錄解析 recipe_id，再取得物品 ID，避免把配方編號當成物品編號。
- 33-byte 格式保留對應的物品識別封包格式；已帶配方 ID 卻缺少目前 Runtime 時，不退回舊格式。
- 自訂清單共用同一正式服務。材料預留、排程回覆與扣料雙重確認、逾時停止不重送均保留。
- 同一物品有多個配方時，完整目錄仍保留所有身分，現有物品型 UI 不猜選其中一個。未知配方索引會明確拒絕解析。

## 驗證範圍

新增 12 項測試，使用經完整動態解析與啟用流程的合成官方資料，驗證一般配方可排程、新版封包位元組、正式網路解碼、自訂排程、扣料後才確認、開始與完成請求、33-byte 格式、來源失效、條件限制、逾時不重送及 UI 按鈕／原因。

三平台 CI 須於提交後確認。這些測試沒有登入正式服，不代表已確認正式服完成製作或產物入包。

## 空排程登入初始化

截圖的材料／設備已符合，但底部顯示「製作排程尚未同步」。ready 原本只由 S64-1 快照設定；登入時未收到此封包，會一直停用加入按鈕。

現在以 S1-11 initial_data_complete 結束登入資料批次，將尚未就緒的初始排程完成初始化，並標記 sync_source。保留此前接收的增量列；已收到的 S64-1、執行中項目、pending 與 uncertain 不被清除。缺少執行中索引仍報錯。不以開啟視窗、設備可用或任意逾時推定同步完成，也不額外發送未確認的同步請求。

既有 12 項動態排程測試不再手動設 ready=True，改經正式 S1-11 解碼與 State.apply 初始化。另新增 6 項案例，覆蓋無 S64 快照的空排程登入到實際命令／按鈕、增量列保留、執行中快照保留、不確定狀態、無關事件及重複結束訊號。正式服結果仍需實際操作驗收。
