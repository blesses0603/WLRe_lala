## 第 05 項：角色與夥伴同步保護

- LaLa 配點 UI 以角色 ID 辨識預覽來源，角色切換時即使兩個角色數值相同，也會清除未送出的點數與舊的等待狀態。
- 戰鬥、事件、自動戰鬥、徘徊、離線、尚未完成 S5-3 同步、配點待確認或結果不明時，配點視窗會停用確認及加點控制；網路指令層仍獨立重新驗證，UI 不是授權來源。
- S8-4 成功通知與五項能力／剩餘點數的伺服器更新必須同時確認，才可解除 pending。配點逾時視為結果不明，禁止自動重送。
- S8-2 夥伴能力暫存依「格位」管理；夥伴刪除或格位被不同 NPC 重新佔用時，丟棄前一位夥伴的舊 S8 快取，避免污染新夥伴數值。
- S19-1／S19-2 只提供 NPC ID 而不是夥伴格位。若擁有多隻相同 NPC ID 的夥伴，不能辨認出戰中的確切格位；LaLa 會顯示格位未確認並阻止含糊的切換操作，避免誤操作。
- 測試涵蓋角色切換、配點上下文限制、部分 S8 更新、逾時成功通知、格位複用及同 ID 夥伴安全規則。
- 仍需正式遊戲伺服器封包實測；此次不加入夥伴配點或猜測未驗證的角色潛能增幅，不修改 C8-1／C19-1／C19-2 格式。
