## 原始門索引去重與稽核

- **相同場景、相同普通門事件 ID**：清單只保留一筆供診斷，
  標上重複 ID，並停用 `direct_eligible`、`direct_door_index`、
  `destination` 與導航座標。只有真實門事件唯一、正式官方資料
  完全核對後才能恢復，不以「第一筆」自動授權。
- **隱藏傳點**：只有場景、來源原始格點、目的場景、NameID
  **完全相同且全部已知**時，清單合併真正重複標記；
  同場景從 H1 重新編號。任何一項不明則留存供人工核對。
- **相同中文名稱、相同單點座標**：不是充分證據。同名不同
  事件 ID、同座標不同目的場景／抵達點均予保留。
- 增加 `portal_duplicate_report` 計數以供 UI 和測試查看；
  官方原始 Bundle、唯讀 CSV 與 Runtime 索引均不刪除。

CI 測試只驗證程式行為與測資；實際遊戲傳點狀態、
C20-8 傳送、場景移動與落點仍須正式服驗收。

## 小地圖精簡顯示（2026-11-02）

依目前需求，傳點清單與地圖圖示都以「來源場景＋已知目的場景 ID」分組，每組只顯示一個代表入口。優先選擇可操作入口，再依目的地核對、正式名稱與來源編號穩定選取；保留該筆原始 ID、位置及實際門事件資訊。不同目的場景即使同名或同座標也不合併。

目的地未知、沒有有效名稱、沒有可定位標記或投影超出目前地圖的項目不顯示；規則同時適用固定 1275 與後續動態官方版本。正式 NameID 或已知目的地名稱可作為標示，名稱未取得的場景佔位文字不作標示。

這是顯示層的分組與隱藏。原始 Runtime、不同抵達點、門事件及完整核對報告仍保留，沒有把清單序號轉成門編號，也不因分組而解除傳送限制。介面分別顯示合併與隱藏的數量。

主畫面進一步只顯示已核對目的地、具有有效實際門編號且 `direct_eligible=True` 的入口。即使參考點已有名稱、位置和已知目的場景，只要門事件未核對完成，仍從主清單與小地圖隱藏；完整核對報告保留這些灰色參考資料。此規則不代表伺服器已接受傳送，也不更動門編號對應或載具條件。
