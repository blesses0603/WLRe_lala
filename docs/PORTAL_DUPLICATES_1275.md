**資料來源**：本次會話既有的 `WLRE_1275_Portal_Link_Audit_20261026.zip`，
其中 `EveDoorLinks_2374_full_readonly.csv` 與
`StageMap_kind_2_3_4_readonly.csv`。
這兩份是過去從 1275 官方資料解出的唯讀稽核結果，
而非當次連線伺服器的動態狀態；表中的名稱為場景名稱或
`NameID`，不得直接當成完整 NPC／傳送點顯示名稱。

**不可把它們的重複 ID 當成重複 C20-8 門索引**。

## LaLa 顯示層處理

- **相同場景、相同普通門事件 ID**：清單只保留一筆供診斷，
  標上重複 ID，並停用 `direct_eligible`、`direct_door_index`、
  `destination` 與導航座標。只有真實門事件唯一、正式官方資料
  完全核對後才能恢復，不以「第一筆」自動授權。
- **隱藏傳點**：只有場景、來源原始格點、目的場景、NameID
  **完全相同且全部已知**時，清單合併真正重複標記；
  同場景從 H1 重新編號。任何一項不明則留存供人工核對。
- **相同中文名稱、相同單點座標**：不是充分證據。同名不同
  事件 ID、同座標不同目的場景／抵達點均予保留。
- 增加 `portal_duplicate_report` 計數以供 UI 和測試查看；
  官方原始 Bundle、唯讀 CSV 與 Runtime 索引均不刪除。

CI 測試只驗證程式行為與測資；實際遊戲傳點狀態、
C20-8 傳送、場景移動與落點仍須正式服驗收。
