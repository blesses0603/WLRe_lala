# 每日／每週任務 Runtime 整合

本功能在獨立開發分支，尚未包含於 main 的 v7.1.1；沒有正式服完整驗收紀錄。

## 資料與介面

主畫面「其他功能」開啟獨立視窗，內含「方舟／組織」分頁；福利只保留魔方、每日任務與每週任務。每日任務的方舟／組織入口會開啟其他功能並選取對應分頁，開啟視窗本身不發送遊戲操作。

- 以當次官方雙 Manifest 身分及 Bundle 長度、MD5、CRC 驗證 DailyTaskData_C／DailyTaskRewardData_C，不使用舊版固定任務筆數。
- 兩張原始表依同一 catalog identity 存入既有 `official_sync/derived_catalogs/resource_inventory.sqlite3`，再由 SQLite 重新解析。任務名稱與獎勵物品需與當次 TextData_C／ItemData_C 相符。
- 任務資料採可選 Runtime 擴充；缺表、格式不合或 SQLite 不可用時明確停用每日任務，其餘 Runtime 功能繼續。
- 「福利 > 每日任務／每週任務」顯示當期群組、進度、活躍值、可領狀態、條件執行方式與暫停原因。

## 已實作的領獎流程

- S124-1 完整進度、S124-2 當期群組、S124-3 標記／進度更新、S124-4 獎勵通知、S124-5 錯誤。
- C124-1 使用已核對的任務 index（u16）；C124-2 使用日／週 refreshKind（u8），一次涵蓋同週期所有可領普通與活動寶箱。
- 登入同步後預設自動領取，遵守全域暫停；亦可關閉或手動領取。關閉視窗不會停止網路執行緒排程。
- 同時只允許一筆要求；任務／寶箱領取標記與對應獎勵通知均確認才接續。含實體物品時還需可靠的背包更新。
- 已要求過的同一目標不重送；伺服器拒絕停止自動領取，20 秒未確認鎖定為結果不明，需重新登入同步。
- 週期切換需重新確認完整快照與群組；進行中的要求遇到角色／官方身分／群組變動則停止，不沿用舊授權。
- 背包與魔方、製作、煉金、遠征、補給、儲藏及協力領獎互斥；既有操作已送出時仍等待原來的確認。

## 任務條件的實際支援範圍

| 條件 | 執行方式 |
|---|---|
| 登入 | 由伺服器同步進度 |
| 時間魔方 | 沿用既有自動開啟；條件是否增加由 S124 決定 |
| 煉金／製作 | 沿用使用者已指定的材料、配方與目標，不自行消耗額外物品 |
| 組織簽到／捐獻 | 沿用其他功能的組織自動流程，初級金幣、每日 3 次目標及本輪 450 金幣上限 |
| 方舟 | 情報員派遣、可驗證一般戰鬥與問答依每日目標接續；問答及其他事件有下列限制 |
| 副本／協力 | 可開啟既有功能視窗，開始／準備仍須手動 |
| 聊天、拍照、商城、交易所、儲值等 | 顯示條件與進度，尚未自動代做 |

C124-3 僅用於原版拍照後的完成通知；本版不會在沒有實際動作證據時發送。沒有實作「所有每日任務一鍵自動完成」。

獎勵包含隨機福袋或未知種類時不自動領取。一般物品／裝備使用保守空位估算，不借用歷史堆疊表；空間不足時顯示等待原因，不刪物品、不付費擴充背包。

## 驗證

- 離線測試覆蓋日／週領取、每週第 9 位標記、普通與活動寶箱、確認順序、物品更新、重複通知、逾時、錯誤、群組更新、角色／版本變動、共享背包鎖與真實網路排程。
- 合成驗證來源涵蓋 Manifest／Bundle 計畫 → SQLite → 當期 Runtime → S124 同步 → C124 要求。
- 原生 Tk 測試覆蓋福利各分頁、選取不送封包、手動領獎及副本入口不自動開始。
- `python -m tools.check_daily_runtime --online` 可核對當次官方資料格式與 SQLite 讀取，只下載資源，不登入遊戲；同名 GitHub Actions 提供獨立驗證工作。
- 正式服仍需檢查：登入同步、已完成項目領取、背包不足後恢復、跨日／跨週重置及各實際條件的進度更新。資料格式驗證與合成測試不等於正式服領獎成功。


## 組織自動流程

- 官方 Guild.lua／UISell.lua：C39-69 簽到，S39-85 個人簽到狀態與 S39-86 結果；C10-5 捐獻走精確的 UISell ID（sellKind=0 不附加 itemIndex）。S39-87 同步可捐資格與剩餘次數，S26 確認金幣。
- 當次 UISellData_C、FormulaData_C、OrganizationFunctionData_C 從驗證 Bundle 經共用 SQLite 載入；只支援已核對的常數價格公式，免費／金幣方案不會轉成鑽石或扣物品方案。
- 官方 1286 資料核對：初級 ID 8、金幣 150／次；中高級 ID 9／10 是通用鑽石，這版拒絕自動使用；組織等級 1～10 每日捐獻上限均為 5。這些是驗證觀測，執行仍讀當次資料，未固定價格或伺服器次數上限。
- 預設啟用自動簽到、初級捐獻，每日總目標 3 次、本輪額度 450 金幣。已捐次數由同版等級上限減 S39-87 剩餘次數取得；登入前已完成的部分不會再做。
- 一次僅送出一筆；捐獻要求額度先保留，收到精確金幣扣除及剩餘次數減一後才接續。有消費 saveIndex 的版本還需對應 S10-5 次數更新。
- 不明金幣異動、重複扣款、資格／組織／角色／版本變動、拒絕或逾時會停止，設定開關不會解除不明結果或清除額度。沒有捐獻成功唯一交易 ID，故不自動重試。
- 設定限本輪連線，重新登入或明確 S10-5 日更通知開始新額度；簽到狀態轉變不會自行重置金幣額度。既有背包／領獎流程共用互斥，簽到可在消費表缺少時獨立處理。
- 正式服待驗收：既有組織登入同步、首日新成員限制、簽到結果順序、三次初級扣款及任務進度、金幣不足、跨日、斷線與重連。

- 已核對快取的官方 1286 資料：20 星球、20 情報員、352 戰鬥事件；第一星球六段基礎價格 120／240／345／445／530／600 星力。價格不是硬編碼；技能折扣使用十分之一百分比，時間加成與 Unity 的中點取偶規則分別計算。
- 1286 戰鬥表比上傳 1262 Lua 多一個逐列布林尾欄。解析器分別核對完整舊／新兩種布局，拒絕歧義、截斷、尾端及重複索引；保留該欄而不賦予繞過條件或消費授權的含義。
- 預設依 S124 當日方舟目標自動接續：一般事件探索 3 次、派遣採集 1 次；已完成的部分不重做。派遣使用第一星球一名空閒情報員，挑選最低已驗證成本，預設 1 小時、本次登入 120 星力上限。設定不清除已要求額度，跨日也不自行增加預算，重新登入才開始新額度。
- C191-1 精確傳送星球、小時、情報員一、情報員二（固定 0）；等待 S191-3 與技能推算時間吻合、S75-24 精確扣除星力及對應 S124 進度增加後才完成。逾時、非預期星力異動、錯誤、角色／版本／任務週期改變時保留額度並停止重送。
- 一般戰鬥事件 C191-4 沿用使用者已啟用的自動戰鬥。需同版事件、可確認獎勵及背包空位；新增情報員、隨機福袋等容量未確認的事件不開始。等待勝利獎勵、精確事件完成、需要的背包更新與 S124 進度；落敗停止方舟自動接續。同時不會自動開始一般副本／協力。
- 問答以 C191-6 取得伺服器題目，使用同版文字顯示四個選項，C191-7 回答一次。未知答案需選擇；伺服器確認答對後保存至私人 `ark_questions.sqlite3`，相同角色與官方資料版本可跨登入重用。題目 ID、完整題目文字及四個選項的文字 ID／內容須完全相符；依文字 ID 對應目前位置，避免選項換序造成錯答。不從錯誤回覆猜測正確答案。
- 主線僅供檢視。交付物品與商人購買尚未自動代做；不刷新事件、不使用鑽石捷徑、不升級技能、不消耗加速道具，也不自動收取採集或搬出方舟倉庫。
- 戰鬥進行期間允許本場戰鬥下令，其他背包／消費服務等待；結果不明時連戰鬥接續一併暫停。全域與獨立暫停只停止後續要求，已送出的操作仍處理確認與逾時。
- 離線驗證包含封包欄位、三方確認順序、扣款／重複／逾時／角色／版本／週期隔離、問答選項與答案、共享互斥、真實 SessionLogic 排程，以及 Manifest → Bundle → SQLite → Runtime 的來源整合。正式服登入同步、星力欄位、派遣實際時間與每日進度、方舟戰鬥、跨日、斷線及安裝包仍待驗收。
- 線上資料驗證可執行 `python -m tools.check_daily_runtime --online --guild --ark`，只下載官方資源、不登入正式服；快取格式核對不等同現在官方版本觀測或遊戲實機驗收。
