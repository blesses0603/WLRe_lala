# 遠征

分頁可設定「任務時間大於幾小時」（預設 0）、最低自動化成功率（預設 75%）、好友度門檻（預設 80）、恢復物品選擇，以及「自動領獎」（預設勾選）。恢復物品預設「自動從背包選擇」，也可指定背包內的單一種類。仍需手動啟動自動化，登入或切換帳號只自動檢查資料、不自動派遣。設定變更後自動依帳號與伺服器分開儲存，包含時間、成功率、好友度、恢復物品與自動領獎；切換帳號或關閉分頁前會完成待儲存內容，重新登入會載入該帳號設定。

## 資料需求

已從使用者提供的官方 1262 `datapackage_data_a.bundle`（快取檔名 `__data`）擷取 `AdventureData_C`、`AdventureLvData_C`，內附 260 筆任務與 10 級遠征資料。資源包大小 54,960 bytes，MD5 `2693bf8dcd6d964fa071dcb5994a614a` 與 DataPackage 1262 索引吻合；檔案 CRC32 為 `55871862`（索引小端序字串 `62188755`）。`expedition_catalog.json` 記錄原始資料與資源包的 SHA256，解析時完整檢查筆數、欄位與檔尾。任務 `spanTime` 單位為分鐘，依 `Text.GetTimeStr` 核對。

直接使用程式內建資料，不提供手動載入資料表／資料夾的操作，也不讀取舊的本機覆寫資料。後續版本隨程式更新。遠征頁由左至右為可用任務、駐紮所夥伴與任務詳情。兩張清單僅保留上下捲動條。可用任務以「任務名稱、所需時間、預估成功率」顯示，獎勵放在右側任務詳情；耗時使用遠征等級減免後的小時／分鐘。獎勵列出遠征經驗、經驗、物品名稱與數量、貨幣種類與數量；機率獎勵另作標記，不視為必得。選取任務可查看完整獎勵、好友度消耗與派遣條件，重新整理後保留選取。

260 筆正式繁體中文任務名稱來自使用者提供的 `datapackage_data_t.bundle` 內 `TextData_C`，依 `name_id` 與官方文字 ID 對照。文字包大小 3,619,162 bytes，MD5 `277be57613f8b1306fc645c63835b2ee` 與 DataPackage 索引吻合，CRC32 為 `d69acf33`（索引小端序字串 `33cf9ad6`）；完整解析 39,901 筆 UTF-16LE 文字並檢查檔尾，只內建遠征所需名稱與地區文字。資源包與原始文字的 SHA256 記錄於 catalog 的 `text_source`／`source_sha256`。

## 執行流程

1. 上線後自動接收 S31-6 駐紮所、S31-13 任務與 S31-19 任務變更，完成初始化後自動送一次 C31-28 校正剩餘時間。不必開啟遠征頁面即可檢查；清單僅列出伺服器提供、遠征等級允許且符合時間門檻的任務，並標示夥伴／同區域條件。這不會使用付費刷新。設定完成後按「啟動自動派遣」。
2. 依遠征等級的千分比減免計算任務時間；沒有使用縮時或支援物品。時間嚴格大於設定值才列為候選，預設 0 小時包含所有正耗時任務。
3. 從駐紮所閒置且不在任何遠征隊伍內的夥伴挑選最多四位，完整搜尋符合派遣條件的組合，選擇預估成功率最高的隊伍；同成功率時優先較少好友度恢復量、較低能力總成本、較少成員及穩定索引順序。遵守解鎖隊伍數量、任務難度與同區域限制。只派遣達到最低成功率者，多個任務符合時先選成功率較高者，再比較較長耗時。
4. 上線與背包更新時自動檢查好友度恢復物品、可用數量；排除已鎖定、被保留、限時或尚未可靠同步的物品。清單不會列出未持有的種類；已指定卻缺貨的種類會明示無可用庫存。
   好友度低於設定值才可自動補充，至少補到設定值與任務需求較高者。自動選擇優先以較少物品達標，同數量時減少溢出；單一種類不足但總恢復量足夠時，逐批使用不同種類，每批均等待確認後再續用。指定單一種類時不換用其他種類。不取用小屋儲物櫃，不購買物品，不解除物品鎖定；不足時停止。
5. C31-27 送出後，必須同時確認好友度達標與對應背包格位扣除，才送 C31-15。出發亦須等待對應任務及成員的 S31-18／13 確認，不預先修改本機派遣狀態。
6. 自動領獎開啟時，優先處理已到期隊伍，包含不符合新派遣時間或成功率門檻的既有任務。依伺服器同步的剩餘分鐘數計時，到期前不會領取；使用 C31-16 與隊伍索引逐隊結算，不使用一鍵全領。
   S31-19 任務表更新使用 50 組（索引 UInt8、任務 UInt16）後接一個 Boolean 顯示旗標；完整消耗後才執行封包結尾檢查，避免伺服器結算後刷新任務表時引發 `ProtocolError`。
7. 依實際任務的一般與特殊獎勵保守計算空格需求，不依賴已有物品可堆疊的假設。官方 1262 版全部任務最多需要預留 2 格。背包資料不可靠或空間不足時等待，清出空間後自動繼續；不刪除物品。未知獎勵類型不自動領取。
8. S31-16 領獎回覆須與目前隊伍索引相符，並確認實際獎勵物品數量已入包，才視為領取完成。允許物品更新早於結算回覆。只領到貨幣或經驗等非物品獎勵時不等待額外物品事件。夥伴閒置狀態仍依伺服器更新，之後才能再次派遣。
9. 派遣、領獎或補好友度操作 20 秒未確認會停止且不重送；停止按鈕不會撤回已送出的操作。未確認狀態需重新登入同步。斷線停止自動化。

## 推薦條件與成功率

260 筆任務各保留四組官方推薦條件及加成。成功率依官方介面公式：基礎值加上完全達標的推薦加成，再除以 10，最高 100%；沒有部分達標加成，也不計未使用的支援物品。任務明細顯示各推薦項目是否達標與實際加成。這是本機預估，實際派遣及結果仍以伺服器為準。

夥伴元素、類型及原始 ID 對照來自使用者提供的官方 `datapackage_data_n.bundle`，大小 334,836 bytes，MD5 `a8f1f15a38fd7a29321cafde833b3a60`，索引 CRC32 小端序字串 `5b74ee38`。完整解析 `NpcData_C` 7,543 筆與 `NpcCareerData_C` 42 筆；來源 SHA256 記錄於內建 catalog。轉生條件採官方介面 `GetCondValue` 的階層加總；官方另一個自動選人輔助函式使用轉生人數，兩者有差異。

## 目前限制

- 支援人數、元素、排除元素、指定原始夥伴（含轉職對照）、真實等級、潛能、五項能力、合計轉生階層及人型／獸型條件。未知夥伴資料不推定達標，成功率顯示為已確認的下限。
- 遠征可與自動戰鬥、徘徊同時啟用，互相不會因功能開關而停止或拒絕啟動。實際進入戰鬥、伺服器事件、活動、製作、煉金或未確認補給時，遠征會暫時等待，狀態解除後自動繼續。
- 補好友度期間僅保留此次使用的背包格位，AI 補給仍可取用其他物品；格位保留至扣料與好友度均確認，逾時則保留至重新登入同步。遠征不再全面阻擋補給與戰鬥道具指令，但仍避免與煉金、製作、切換出戰夥伴混用。
- 不自動存入／領出駐紮所夥伴。取消勾選「自動領獎」時，需手動領取遠征結果，夥伴才可再次派遣。
- 協定以 1262 Lua 靜態核對，資料表已使用使用者提供的官方實際資源驗證；尚未實測正式服派遣。

## S31-15 出發回覆相容性（2026-10-19）

新診斷 Log `health-23484.log` 於 19:01:16 記錄 `ProtocolError`、`packet_main=31 packet_sub=15 packet_stage=decode`，並定位 `expedition.py:72 > wire.py:50:end`。官方 1262 `ExpeditionMgr.RevExpeditionStart` 只做 UI 提示與隊伍切換，**不解析任何 S31-15 本文欄位**。舊版 LaLa 雖然不讀取欄位，卻對本文執行嚴格 `r.end()`，當伺服器包含額外位元組時會直接以 `client_error` 結束連線。

現在只針對 **S31-15** 略過官方未定義、未解讀的本文，事件只附帶其長度 `extension_bytes`，不保存原始封包內容或推測未知欄位用途。**S31-16、S31-19 與其他已知資料結構仍維持嚴格長度驗證**，不更改遠征領獎時序、結果確認或失敗重試策略。測試驗證空本文、非空本文與完整連線接收流程皆不因這種格式差異發生 `client_error`；仍須正式伺服器實機驗證。
