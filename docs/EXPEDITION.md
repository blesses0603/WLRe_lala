# 遠征

分頁可設定「任務時間大於幾小時」（預設 5）、好友度門檻（預設 80）、可消耗的恢復物品，以及「自動領獎」（預設勾選）。仍需手動啟動自動化，登入或切換帳號不會自動啟動；預設不使用恢復物品。設定依帳號與伺服器分開儲存。

## 資料需求

已從使用者提供的官方 1262 `datapackage_data_a.bundle`（快取檔名 `__data`）擷取 `AdventureData_C`、`AdventureLvData_C`，內附 260 筆任務與 10 級遠征資料。資源包大小 54,960 bytes，MD5 `2693bf8dcd6d964fa071dcb5994a614a` 與 DataPackage 1262 索引吻合；檔案 CRC32 為 `55871862`（索引小端序字串 `62188755`）。`expedition_catalog.json` 記錄原始資料與資源包的 SHA256，解析時完整檢查筆數、欄位與檔尾。任務 `spanTime` 單位為分鐘，依 `Text.GetTimeStr` 核對。

後續更新可使用分頁「載入官方遠征資料表」，依序選擇兩份原始二進位資料；本機資料表會優先於內附版本。畫面中的任務先以 ID 顯示，中文任務名稱另需 `TextData_C`，不自行編造名稱。

## 執行流程

1. 登入後等待 S31-6 駐紮所與 S31-13 遠征資料同步，載入資料表後按「啟動自動派遣」。
2. 依遠征等級的千分比減免計算任務時間；沒有使用縮時或支援物品。時間嚴格大於設定值才列為候選，剛好 5 小時不符合預設門檻。
3. 從駐紮所閒置且不在任何遠征隊伍內的夥伴挑選最多四位，先找不必用恢復物品的隊伍。遵守解鎖隊伍數量、任務難度、同區域限制與支援的隊伍條件，優先派遣符合條件中耗時最長者。
4. 好友度低於設定值才可自動補充，至少補到設定值與任務需求較高者；每次僅用背包內指定物品與必要數量。不取用小屋儲物櫃，不購買物品，不解除物品鎖定。不足時停止。
5. C31-27 送出後，必須同時確認好友度達標與對應背包格位扣除，才送 C31-15。出發亦須等待對應任務及成員的 S31-18／13 確認，不預先修改本機派遣狀態。
6. 自動領獎開啟時，優先處理已到期隊伍，包含不符合新派遣時間門檻的既有任務。依伺服器同步的剩餘分鐘數計時，到期前不會領取；使用 C31-16 與隊伍索引逐隊結算，不使用一鍵全領。
7. 依實際任務的一般與特殊獎勵保守計算空格需求，不依賴已有物品可堆疊的假設。官方 1262 版全部任務最多需要預留 2 格。背包資料不可靠或空間不足時等待，清出空間後自動繼續；不刪除物品。未知獎勵類型不自動領取。
8. S31-16 領獎回覆須與目前隊伍索引相符，並確認實際獎勵物品數量已入包，才視為領取完成。允許物品更新早於結算回覆。只領到貨幣或經驗等非物品獎勵時不等待額外物品事件。夥伴閒置狀態仍依伺服器更新，之後才能再次派遣。
9. 派遣、領獎或補好友度操作 20 秒未確認會停止且不重送；停止按鈕不會撤回已送出的操作。未確認狀態需重新登入同步。斷線停止自動化。

## 目前限制

- 支援可由現有資料判斷的無條件、人數、真實等級、潛能、五項能力、轉生階層與指定夥伴 ID 完全相同的條件。元素、人型／獸型，以及需職業轉換對照的指定夥伴條件，資料不足時會跳過。
- 正在戰鬥、事件、活動、自動戰鬥／徘徊、製作、煉金或未確認補給時不派遣。派遣啟用／等待確認期間會阻擋相衝突的消耗操作。
- 不自動存入／領出駐紮所夥伴。取消勾選「自動領獎」時，需手動領取遠征結果，夥伴才可再次派遣。
- 協定以 1262 Lua 靜態核對，資料表已使用使用者提供的官方實際資源驗證；尚未實測正式服派遣。
