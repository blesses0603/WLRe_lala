# 製作清單空白修正

官方動態配方已載入 RECIPES，但 activate_dynamic_recipes 將其標為 read_only；清單和設備分類原先都使用 confirmed_unlocked 篩選。該函式排除唯讀配方，導致配方雖存在，畫面仍顯示「已解鎖 0 項」、沒有設備或卡片。

## 修改行為

- 瀏覽清單顯示已載入配方，不以「能否立即製作」決定是否隱藏。
- 設備分類來自全部已載入配方。分類名稱改為「全部配方」。
- 配方卡片顯示實際狀態（參考配方、圖紙／活動條件、設備或材料狀態），不將可瀏覽冒稱為已解鎖。
- 「只列小屋已有設備」預設不勾選；使用者明確啟用且小屋同步完成後才依設備篩選。尚未同步小屋不會清空清單。
- 分頁標籤改為「配方 N 項」。沒有結果時區分來源未載入、搜尋無結果、收藏無結果與設備篩選，並提供對應說明。
- 可操作配方維持優先排序；唯讀或有條件配方仍可查看材料、產量與設備。選取、搜尋、收藏與分頁仍保留。

本次處理清單顯示問題，沒有將配方顯示狀態直接當成伺服器已完成製作，也沒有改變封包欄位。

## 回歸

新增七項無視窗測試與一項實際 Tk 視窗測試，包含所有配方都未被 confirmed_unlocked 認可時仍正常顯示、唯讀狀態、設備篩選、未同步小屋、搜尋與收藏、空結果原因，以及實際視窗的卡片／設備／材料表。三平台 CI 重新執行，未將待確認結果標記為通過。
