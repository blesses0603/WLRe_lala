# Phase 0：官方伺服器連線實作盤點（桌面版）

> 狀態：靜態程式碼檢查。沒有在本次盤點中連線官方正式伺服器、登入帳號、送出遊戲操作或執行測試。
> 基準：main commit `2dd6694b46e22e6e0102195036a859e3720a083c`（桌面版 v0.6.1）。

## 1. 已確認的程式位置與責任

| 路徑 | 已確認責任 | 尚不能據此宣稱 |
|---|---|---|
| `wlre/network/client.py` | `run_client(host, port, profile, ...)` 建立 TCP 連線、送出登入封包、讀取與拆解封包，將事件交給 State／SessionLogic；包含 `verify_account()` 驗證流程。 | 正式伺服器目前可登入、整個登入流程成功、所有遊戲操作均與伺服器相容。 |
| `wlre/network/protocol.py` | 建立登入／選角／移動／戰鬥等封包，解析伺服器回覆；登入帳密目前只接受 ASCII，非 ASCII 編碼明確視為未驗證。 | 每個封包布局都已經正式伺服器端到端驗收。 |
| `wlre/network/wire.py` | Packet、Reader／Writer、長度框架與 XOR 編碼／解碼。模組註記仍要求以真實客戶端擷取驗證 outbound codec。 | 僅通過本機編解碼測試就等同官方協定相容。 |
| `wlre/resources/default_profile.json` | 有連線端點、XOR、platform/language 設定及 PCAP 證據摘要。 | 端點仍在線、屬於目前官方正式服、可直接登入或現有參數已被官方客戶端獨立驗證。該檔明確寫著「observed PCAP; official live client not tested」。 |
| `wlre/storage/defaults.py` | 驗證預設連線設定的欄位、端點及數值範圍。 | 只驗證設定格式，不會驗證伺服器身份或實際連線結果。 |
| `tests/test_network_command_envelope.py` | 使用 mock socket 測試命令驗證、送出前封包檢查、送出觀察與串流拆框。 | 這些測試不是官方伺服器 E2E。 |

## 2. 連線流程（由程式碼確認）

1. 呼叫端提供 host／port、profile 及使用者輸入的帳號／密碼。
2. 如啟用 `verify_first`，先向 profile 的 verification endpoint 送出 login kind 0 驗證；成功不等於正式遊戲登入完成。
3. 正式連線使用 login kind 2，之後解析登入結果、角色列表及遊戲狀態。
4. 程式的 `sent`／本機命令觀察只證明資料已交給本機 socket 傳送流程，不證明伺服器已接受或完成遊戲動作；必須觀察對應伺服器回覆及權威狀態。
5. 連線結束原因與部分錯誤階段有診斷紀錄，但不得把連線建立成功當成登入成功。

## 3. 現有證據等級

- **已確認：** 程式存在 TCP client、登入／驗證流程、封包編解碼、回覆解析及 mock 測試。
- **已確認：** 預設 profile 的證據描述是 PCAP 觀察，且明確標示官方 live client 尚未測試。
- **未確認：** 預設端點目前是否為官方正式服的有效端點、官方正式服是否接受本程式的登入封包、實際帳號登入是否成功。
- **未確認：** Battle、Map 各操作是否在當前正式服被接受，以及伺服器端狀態是否符合預期。
- **未執行：** 本次沒有執行 pytest、socket 連線、正式登入、桌面 EXE 建置或端到端測試。

## 4. 下一步驗收順序（直接正式服測試策略）

### Gate A — 本機安全與協定測試
- 執行既有網路／協定測試，確認測試實際結果；不以測試檔存在作為通過證據。
- 對登入封包、FrameDecoder、TCP 分段／合併封包、逾時、EOF、錯誤回覆與敏感資料不落 Log 增加可重現案例。
- 核對 profile 來源與版本，保留 PCAP 的來源、時間、完整性及允許用途記錄。

### Gate B — 低風險連線確認
- 先確認正式服端點來源及目前有效性，再只測試 TCP 可達性；不提交帳密、不送出遊戲指令。
- 若端點無法由可信來源確認，不把連線成功或失敗歸因於協定正確性。

### Gate C — 帳號驗證與正式登入
- 由帳號持有人在本機安全輸入測試帳號；不得把密碼貼入 PR、Issue、Log 或對話紀錄。
- 先測試明確定義的帳號驗證流程，再由使用者明確啟動正式登入；記錄經去識別化的階段、結果代碼及時間。
- 不在自動測試中保存、重播或重試真實憑證；遇到未知結果時停止，不重複送出可能造成副作用的操作。

### Gate D — Battle／Map 真實伺服器驗收
- 登入成功後先只觀察權威狀態與伺服器回覆；再由使用者逐項觸發可逆、低風險的手動操作。
- Battle 先驗證回合／角色狀態及手動單次指令；之後才驗證自動戰鬥、去重與戰後流程。
- Map 先驗證位置／場景回覆；再測試短距離移動與可確認的場景切換。傳送／消耗資源操作必須獨立列為高風險案例。
- 每項案例分開記錄「本機送出」「收到伺服器回覆」「權威狀態改變」三種證據，不將其混為同一個 PASS。

## 5. 安全與驗收停止條件

- 不記錄或上傳帳號密碼、原始登入 payload、session token、聊天內容或完整 PCAP 中的個資。
- 不自動進行重複登入、重複戰鬥指令、購買／交易、領獎、消耗物品或其他不可逆操作。
- 連線／登入結果不明、封包格式不符、伺服器回覆未知或狀態不同步時，停止該案例並保留最小必要診斷。
- 正式服 E2E 需要實際測試紀錄；mock／合成封包測試通過不替代正式服驗收。

## 6. 結論

目前可以確認「有實作 TCP client 與遊戲協定處理」，但**不能宣稱目前程式已成功登入官方正式伺服器**。下一個實際步驟應先執行本機測試並核對端點證據，再進行不送帳密的 TCP 可達性確認；帳號登入與 Battle／Map 測試需由帳號持有人在安全條件下逐階段驗收。
