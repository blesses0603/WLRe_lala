# LaLa 全新重製計畫（桌面版）

> 文件性質：重製規劃與盤點基線，不代表新客戶端已實作或通過驗收。盤點基準：2026-10-27 的 `main`。

## 目標

從零建立新客戶端，舊版僅作為功能、協定與行為參考。桌面版與 Android 共同規劃、分階段交付；維持各自獨立版本號與建置流程。視覺方向為深藍科技風。

## 現況基線

- Repository：`blesses0603/WLRe_lala`
- main 版本：`v0.6.1` 開發版；本次讀取 README 的 blob SHA：`d4425fa127f421ad7137f7090697a2cbd6971a9c`
- 技術：Python、Tkinter/ttk；已有 `wlre/core`、`wlre/network`、功能模組與回歸測試。
- README 明確指出正式服逐功能 E2E、正式 Release 與安裝包仍待完成。舊版功能存在不代表每項均已正式服驗收。

## 重製原則

1. 新架構與舊版隔離，先建立新模組，再逐功能遷移經驗與協定證據。
2. 不直接重寫或覆蓋既有功能；採獨立分支、PR 與階段驗收。
3. 核心業務邏輯不依賴 UI；UI 不直接操作 socket 或任意修改核心狀態。
4. 未確認的伺服器結果、逾時及斷線狀態必須明確標示未知；不得假設成功或自動重送可能產生副作用的命令。
5. 未經來源驗證的資源、封包欄位與伺服器行為不得推測啟用。
6. 不刪除舊資源、不更動版本號、不建立 Release Tag，除非對應階段驗收完成。

## 目標模組

- `domain`：角色、隊伍、戰鬥、地圖、物品、遠征、社交等平台無關模型。
- `application`：用例、服務協調、狀態同步、操作排程與資源預留。
- `protocol`：封包編解碼、連線生命週期、請求／回覆關聯與伺服器權威狀態。
- `resources`：版本閘門、來源驗證、快取與校驗收據。
- `desktop_ui`：深藍科技風桌面介面；只呈現狀態與呼叫用例。
- `tests`：單元、協定、契約、回歸及端到端驗收清單。

實際 UI toolkit 與套件切分需先完成技術選型 ADR，不預先強制更換語言或大規模重構既有程式。

## 分階段交付

### P0 — 盤點與行為基線
- 將既有功能標記為：已實作、唯讀、部分實作、停用、待正式服驗收。
- 盤點 battle、map、accounts、items、expedition、social 的 UI、服務、封包、資料來源、測試與風險。
- 建立桌面／Android 功能對照矩陣及技術選型 ADR。

### P1 — 新架構骨架與設計系統
- 建立新核心模組邊界、事件模型、錯誤型別、命令生命週期與 CI。
- 定義深藍科技風色彩、字級、間距、卡片、按鈕、狀態與導覽規範。
- 先交付不連正式伺服器的主框架與測試替身。

### P2 — 帳號、連線與狀態同步
- 多帳號隔離、登入／選角狀態、連線中斷與重連狀態。
- 驗證封包、資源與協定版本；拒絕未知或不完整狀態。
- 以 fixture 與契約測試驗證請求／回覆關聯。

### P3 — Battle
- 先完成戰鬥狀態模型、戰場／角色／夥伴資料及手動操作流程。
- 再逐項接入已驗證的戰鬥封包；自動戰鬥須有明確狀態、停止條件與回歸測試。
- 未經正式服 E2E 驗證的副作用操作維持停用。

### P4 — Map
- 地圖、座標、場景切換、小地圖呈現與可驗證傳點資料。
- 區分「地圖可顯示」與「伺服器已確認移動／換圖」；未知結果不偽裝成功。
- 資源版本與來源校驗失敗時禁止使用不相容導航資料。

### P5 — Items 與其他功能
- 依序處理背包／道具、補給、製作、遠征、夥伴、社交及紀錄。
- 涉及消耗物品、交易或領獎的操作，須先完成伺服器回覆與資源預留證據。

### P6 — 驗收與交付
- 執行單元、整合、跨平台契約、打包及人工正式服 E2E。
- 分開回報 CI、桌面安裝測試與正式服功能驗收；未完成不得宣稱正式發布。

## 每階段完成條件

- 有明確範圍、程式碼審查與測試證據。
- 不破壞舊版既有功能與建置流程。
- 新舊功能差異、未完成項目及風險寫入文件。
- PR 標題依規範採繁體中文與版本格式；版本只在正式納入且符合版本政策時更新。
