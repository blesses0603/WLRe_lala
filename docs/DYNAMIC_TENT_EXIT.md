# 動態帳篷場景與離開操作

## 原因

角色進入 63503 後已收到自家家具與本機換圖，舊帳篷控制仍只接受 10299／10298／10000，因而卡在「等待房屋場景確認」。控制介面也只有進入，沒有離開帳篷的動作。

## 修正

- 每次進入都記錄來源場景與本次進入脈絡。自家家具及本機換圖回覆兩者到齊，且新場景屬既有房屋模板或目前 Runtime 未列出的私人實例，才確認進入；不只憑未知場景 ID 就判定為房屋。接收先後順序均可，延遲的完整證據可解除進入逾時。
- 室內保存當次 interior_scene 與 return_scene；大廳及製作工具列依確認狀態切換「進入／離開帳篷」。
- 離開使用既有 C20-8 + UInt16 門索引，不新增猜測的 C65 操作。索引由當次官方 Runtime 的房屋模板門事件與 StageMap／EveDoorLinks 目的地交叉核對，排除室內樓層連線，只在出口索引唯一時送出。**不固定寫死門 1，不使用歷史表的靜態目的地 12050，不以小地圖圖片是否存在作為離開前提。**
- 歷史來源核對：主分支既有 portals.json（1536ad51）中三個房屋模板均為已核對的觸碰出口；本次只確認既有 C20-8 路徑的適用性。實際送出的索引仍由目前官方 Runtime 決定。
- 送出離開請求不修改角色位置，不立即標示已離開；等待本機伺服器位置返回來源場景。拒絕、重複送出、戰鬥與逾時保護保留，逾時不重送。缺少或矛盾的出口資料明確報錯。
- 私人房屋仍可能沒有場景表／小地圖圖片，這不再妨礙獨立的離開按鈕；沒有自行補畫未驗證地圖。

## 驗證

新增 13 項無視窗回歸與 1 項實際 Tk 按鈕回歸，覆蓋 63503、封包先後順序、他人資料、一般場景、延遲確認、目前來源門索引、沒有小地圖的離開、樓層連線排除、拒絕／逾時及 UI 切換。使用合成 Runtime 與封包，不代表正式服已確認離開；新 CI 與正式操作結果待確認。


## 出口綁定格式相容修正（2026-11-02）

動態門配對改為 `matched_touch_region=True` 後，舊帳篷服務仍只接受 `matched_stage_map=True`，因此 63503 已確認進入，卻在送出離開指令前被錯誤阻擋。出口查找現在接受同版實體觸碰門配對，仍核對實際 index、事件座標與模板內唯一性，不要求小地圖圖片。

優先使用明確指向房屋模板之外的已驗證出口。若沒有這類固定目的地，只有當進入流程已記錄有效返回場景，且 StageMap-only 的有名入口、PlayerTouch、實際門編號與綁定均確認時，才允許單次手動觸發；不猜門 1，也不將返回場景寫成假造的門連線。原有樓層連線不能被當成已驗證戶外出口。

送出 C20-8 後仍保留帳篷內狀態，只有伺服器確認返回進入前場景才標示離開。拒絕／逾時不重送，也不從小屋內呼叫收帳篷。正式服實際離開仍待驗收。
