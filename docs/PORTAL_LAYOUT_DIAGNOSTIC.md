# PR #57 門資料格式診斷修正

## 畫面的意義

`destination_links_layout_unrecognized` 表示 StageMapData 名稱已取得，但 EveDoorLinks
沒有通過結構辨識。不能從這個狀態直接斷言官方新版改過欄位，也不能判定下載損毀。
原本所有解析例外被壓成同一個狀態，所以畫面無法分辨具體失敗原因。

門事件、傳點名稱和門連線是獨立來源。名稱可顯示不代表門連線、倍率與座標交叉核對也已通過。
尚未核對時顯示座標未確認並停用傳送的行為保留。

## 本次修正

- 官方 1262 Lua `Data.LoadEveDoorLinks` 先尋找「事件ID」，再解析 `=` 右側的編號。
  Python 舊正規式只接受 `事件ID=編號`。現在明確接受這個形式與 `[事件ID]=編號`，
  保持整行匹配、UTF-16LE、編號／座標範圍、三組連線欄位等檢查。
- 結構辨識保留固定 `reason_code`，不輸出原始資料、路徑或例外內容。
- 逐圖核對視窗分別顯示：標頭未辨識、重複／無效編號、連線欄位不符、
  UTF-16LE 編碼不符、記錄長度不符等原因。
- 一般狀態文字改為「格式未通過解析」，不再把所有例外當作「新版欄位變更」。

使用者的 1275 EveDoorLinks 實際快取尚未在目前雲端取得，因此不能聲稱該快取
一定就是方括號標頭，也不能宣稱所有實際門連線已驗收。更新後重新啟動 LaLa，
既有官方來源驗證通過的快取會重新解析；若仍未通過，具體診斷能指出下一個核對方向。
不要求使用者手動準備新的資料 ZIP。

## 驗證

門資料相關 38 項測試通過，含 BOM／CRLF 與方括號標頭、既有純文字標頭、
欄位長度錯誤分類、診斷不洩漏來源及未知格式安全拒絕。
正式伺服器換圖尚未實測；所有來源與單次手動傳送限制維持。

完整回歸 1117 項：1115 通過、2 跳過。另保留已驗證的長文字視窗高度修正，
避免目前雲端字型環境下既有排版測試失敗；兩個問題分開提交。
