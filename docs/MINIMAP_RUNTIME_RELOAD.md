# 動態 Runtime 切換後的小地圖重載

畫面在登入後第一次進入場景 12170 顯示「沒有原始小地圖」。程式存在以下載入順序問題：

1. HomeMap 在預登入 Runtime 驗證前建立 SmallMaps，來源版本停留在歷史基準。
2. show_map 先用舊 SmallMaps 查詢目前 Runtime 場景，因版本不同失敗。
3. refresh_portals 隨後才替換資料來源，卻沒有重新讀取圖片。
4. 後續角色狀態仍在同一場景，未再次呼叫 show_map，畫面持續空白。原先 Canvas 還將所有失敗統一標成「沒有原始小地圖」。

修正將 Runtime 來源更新抽成 refresh_runtime_sources，在任何場景投影／圖片查詢前完成。set_state 同時追蹤完整 Catalog key；即使數字版本與場景 ID 相同，只要 Runtime 身分變更，就清除舊圖、路線及投影並重新載入。已綁定來源與已載入地圖各自記錄 key，避免傳點更新先綁定後漏掉重載。

圖片依然從完整初始資料庫內的小地圖 BLOB 取得，場景／模型及投影使用當次官方 Runtime，不復原舊資源檔，也不以歷史場景對應代替缺少的新版場景。真正缺圖或缺少場景時顯示實際原因，不以改文字掩蓋失敗。

新增回歸以實際種子圖片、合成的已驗證 Runtime 場景 fixture 測試 12170 首次載圖、同場景 Runtime 更換與重發、傳點先更新、相同來源避免重解碼、Runtime 失效清除、缺少官方場景拒絕歷史回退，以及 Canvas 顯示實際錯誤。合成 fixture 不代表已取得使用者當次正式服 ScenesData_C 或完成該場景的線上像素驗收；三平台 CI 重新執行，結果另行確認。


## 其他功能同類問題檢查

同一輪檢查亦發現並修正：

- 遠征頁在登入前只載入一次任務／夥伴目錄。改以完整 Catalog token 重載，清除舊隊伍預估、計算 Future 和定時器；較晚完成的舊工作不再覆蓋新版本。自動遠征偵測來源更換後停止舊派遣決策，既有待確認回覆仍由伺服器處理。
- 製作頁雖共享更新後的 RECIPES，卡片、設備和詳情的快取未包含資源版本。現在來源切換會清除快取與舊選取，重新讀取收藏原檔，不改寫或丟失使用者檔案。舊自訂清單中已不存在的配方顯示「配方待更新」，避免 KeyError。
- 背包重繪鍵只看伺服器道具數量，忽略名稱及 Runtime 變更。現在會更新同 ID 的名稱、價格與限制等物品詳情。物品 metadata 也固定從單一 Runtime 快照取得，避免名稱／價格與來源版本混用。
- 傳點操作原本只區分是否為官方版本，可能保留另一個官方版本的目錄。現在依完整 Catalog token 重建，舊的等待／步行觸發在來源變更後取消，不會把舊門 index 送給新來源。
- NPC／商店／選項／歷史視窗會在來源切換時關閉並清除舊選取，避免顯示或使用舊索引。重新開啟讀取同一批已更新的 NPC、對話與物品資料。
- 功能資源標籤不再拿目前已驗證的 Runtime 與固定 1275 的分類報告比較。自動戰鬥設定中的物品名稱亦即時取自當次物品資料，不沿用供給清單的快取文字。

本次檢查的是 Runtime 切換與既有快取更新問題，沒有將獨立的歷史參考資料（例如明確標示 1262 的副本目錄、未有新版來源的技能／效果表或導航網格）冒充已驗證的新版本解析資料。

額外新增 12 項消費端回歸，涵蓋遠征背景結果、收藏檔保留、背包同數量更新、傳點換來源、舊待送觸發取消、遠征來源切換、單一物品快照、功能標籤、缺少配方與戰鬥物品名稱。這些回歸與小地圖測試一併交由三平台 CI 執行，未預先宣稱通過。
