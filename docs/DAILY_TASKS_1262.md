# 每日／每週任務自動化：第一階段協定與狀態同步

## 資料來源與範圍

- 1262 Lua：`Logic/Activity.lua` 的 `DailyTask`、`Logic/Protocols/Protocols_124.lua`、`Data/DailyTaskData.lua`、`Data/DailyTaskRewardData.lua`。
- S124-1：每日／每週活躍度、8／12 項進度、領取位元標記及限時活動旗標（固定 33 bytes）。
- S124-2：當前日／週群組（2 bytes）。
- S124-3：更新活躍度與領獎標記（kind 1），或單項進度（kind 2）。
- S124-4：獎勵通知。此階段**只確認存在通知**，不以通知推測特定任務已成功領獎。
- S124-5：伺服器錯誤碼（含條件未完成、已領取及背包空間不足）。
- 任務領獎：原版 `C124-1 + task.index:u16`；活躍寶箱：`C124-2 + refreshKind:u8`。這兩個指令已確認，但**目前不自動發送**。

## 安全設計

本次只加入登入後伺服器下發的每日任務唯讀進度，以及離線可測試的候選判斷器。
不可把每日任務序號 1～8／每週序號 1～12 當成 C124-1 的任務 `index`。
正式任務對照需取得 1262 `DailyTaskData`、`DailyTaskGroupData` 及 `DailyTaskRewardData` 二進位表（含對應中文 TextData）；不可單憑 Lua 類別格式編造每個任務的目標數值。

完成這份資料核對之前，**不提供假任務名稱、假完成率或可按下的自動執行按鈕**；不自動購物、充值、聊天、消耗材料或開始副本。
即使之後可領獎，也必須逐筆等待 S124 狀態同步，未知結果不得盲目重送，且登入不會自動啟用自動化。

## 第二階段規劃

1. 解析官方完整任務／獎勵資料，核對 `group`、`id`、`index`、`cond.kind`、目標條件與獎勵。
2. 加入逐筆領取佇列、伺服器成功確認、逾時結果不明安全鎖及背包空位檢查。
3. 對已有 LaLa 執行能力且無資源風險的任務提供選擇性自動完成，其他任務顯示人工處理原因。
4. 依遊戲伺服器日界／週界同步重置，而非用手機或電腦本地時間猜測。
5. 補充正式伺服器端到端驗收，才可標記「每日任務自動完成」已可用。
