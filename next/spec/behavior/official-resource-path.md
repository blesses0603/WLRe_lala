# 官方版本對照表：`ResourcePath_{PC,ANDROID,IOS}.dat` 與 `DownloadUrl_*.txt`

> 來源：2026-10-27 以 `next/tools-python/probe_official.py` 實際 GET 官方 CDN 根目錄取得，並用 `describe` 分析。
> 證據等級：`official_cdn`（官方伺服器實際回應；**沒有**與官方客戶端 Lua 的讀取程式逐行核對）。
> 對照參考：舊版 `wlre/services/official_version.py` 的 `parse_resource_path()`（`reference_impl`）。

## 1. `ResourcePath_*.dat`

**它不是二進位檔。** `PLAN.md` 原本記為「二進位、格式未知」。實際內容是 UTF-8 的 JSON 文字，
副檔名是 `.dat`，伺服器回 `Content-Type: */*`。

| 項目 | 觀察結果 |
|---|---|
| 編碼 | UTF-8，**沒有 BOM** |
| 換行 | CRLF；最後一行 `]` 後面**沒有**換行 |
| 結構 | 頂層是陣列，每個元素是一個 `{"ExeVer": 字串, "DataVer": 字串}`，一個元素佔一行 |
| 語法怪癖 | 最後一個元素後面有**多餘的逗號**（`},\r\n]`），標準 JSON 解析器會拒絕 |
| 大小 | PC 164 bytes（4 筆）；ANDROID、IOS 各 124 bytes（3 筆） |
| `ExeVer` | 三段數字版號（例：`1.3.0`），代表**客戶端程式**版本 |
| `DataVer` | 三段數字版號（例：`1.3.21`），對應 CDN 根目錄底下的**版本資料夾名稱** |

2026-10-27 的實際內容（只有版本號，沒有位址，可公開）：

```
PC：     1.1.3、1.1.4、1.2.0、1.3.0 → 全部對應 DataVer 1.3.21
ANDROID：1.1.3、1.2.0、1.3.0        → 全部對應 DataVer 1.3.21
IOS：    1.1.4、1.2.0、1.3.0        → 全部對應 DataVer 1.3.21（與 ANDROID 同為 124 bytes，但第一筆 ExeVer 不同）
```

### 解析規則（新版實作要遵守）

1. 只接受 UTF-8 文字，不是 `[` 開頭就拒絕（例如收到 HTML 錯誤頁）。
2. 只允許移除「最後一個元素後面、緊接在結尾 `]` 之前」的那一個逗號；其他語法錯誤一律拒絕。
   舊版的作法相同：`re.sub(r",(?=\s*\]\s*\Z)", "", data, count=1)`。
3. 每個元素必須剛好有 `ExeVer` 與 `DataVer` 兩個字串欄位，格式都是 `數字.數字.數字`；任何一筆不合法就整份拒絕。
4. 用「本機客戶端的 ExeVer」查表，必須**剛好一筆**相符，否則拒絕，不得猜測 DataVer。
5. 表中有比本機更新的 ExeVer 時，要另外回報「官方有新版客戶端」，不可默默沿用舊 DataVer。

### 舊版額外處理、本次沒有觀察到的情況

舊版 `_decode_resource_map()` 也接受 gzip 與 UTF-16 BOM。這次三個平台的檔案都**沒有**出現這兩種形式；
新版要不要保留這兩條路徑，需要有意識地決定（建議：保留拒絕條件，不主動支援，除非實際觀察到）。

## 2. `DownloadUrl_*.txt`

| 項目 | 觀察結果 |
|---|---|
| 編碼與換行 | UTF-8、無 BOM、CRLF，結尾沒有換行 |
| 結構 | 與 `.dat` 相同風格：陣列，最後一個元素後有多餘逗號 |
| 元素欄位 | `Version`（2 字元的字串）、`Url`（完整網址字串） |
| 大小 | PC 64 bytes（1 筆）；ANDROID 181、IOS 152 bytes |

`Url` 的實際值**不寫入**本 repo。它的用途（客戶端下載頁或安裝包位址）尚未核對官方 Lua，標示「尚未確認」。

## 3. 與版本資料夾的關係

- 根目錄目前有 `1.0.0`、`1.3.20`、`1.3.21` 三個版本資料夾；`.dat` 只引用 `1.3.21`。
- `1.3.20` 與 `1.0.0` 仍可列表與下載，但不在對照表中。新版**只能**用對照表選出的 DataVer，不得自己挑「最大的資料夾」。
