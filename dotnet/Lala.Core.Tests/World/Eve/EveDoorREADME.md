# Offline Eve door projection

`EveDoorParser` ports `wlre/services/world/doors_1275.py` and every helper. It is
separate from `EveV115Parser`: source validation order and scope differ. The
public `ParsePinned1275` always checks the reviewed 1275 Eve source SHA-256 and
1262-scene count. There is no custom-pin overload. Internal `ParseLayout` supports
tests and the offline candidate composer, without claiming official provenance.

The immutable output retains ordered door geometry, original pre-prefix name
hex, strict CP950 names, byte event references (including duplicates), PlayerTouch
records, unsigned condition values, signed effect values, conditional convey
transfers and missing convey IDs. Destination 0 is retained, not judged valid.
`DestinationDecoded` reports referential decoding only. All runtime, packet,
travel and asset-ready authority flags remain false.

The door source deliberately accepts overlapping scene windows, ignores zero NPC IDs
and duplicate indices inside skipped NPC records, ignores unrequested event condition meaning,
and checks only the group/convey directory entries. The stricter full Eve parser
may reject these same inputs. The candidate composer still performs its own
independent full Eve parse. The door port does not silently strengthen these
source checks or invent validation for destination IDs, direction or link fields.

## Limits and explicit divergence

Input is limited to 32 MiB, 4096 scenes and the source's existing 4096 NPC/door/
Mine/Goods/Event records per scene. Groups and conveys preserve the source's
uint16 count limit. A cumulative 1,000,000 retained-unit budget additionally bounds
repeated scene windows, retained parameters and duplicate event references.
One synthetic fixture documents the resulting rejection of a source-valid input;
it is a safety divergence, not parity. Events are resolved once and shared only
as immutable values. Input snapshots are detached; no payload remains in outputs.
Cancellation is checked before allocation, hashing, each read and projection loop.

## Oracle and verification

Run from repository root:

```sh
python3 dotnet/Lala.Core.Tests/World/Eve/generate_eve_door_cp950.py
python3 dotnet/Lala.Core.Tests/World/Eve/generate_eve_door_vectors.py
dotnet test dotnet/Lala.Core.Tests/Lala.Core.Tests.csproj -c Release --filter FullyQualifiedName~EveDoorTests
```

The generator calls the actual retained decorated Python parser. It pins reviewed
source hashes with **CRLF-only** normalization, records exact error messages and
bounded diagnostic checkpoints, and fixes gzip metadata. 928 cases occupy about
113 KiB compressed. Theory discovery yields scalar names and row indices only;
JSON loads lazily from a hash-verified bounded resource and failure messages are
rendered only on assertion failure. The corpus covers per-byte truncation, source
limits, validation ordering, ignored trailing sections, every helper and multiple
conditional transfers. It includes pinned rejection, not a fake pinned success.

CP950 uses a lazy 39,564-byte code-owned mapping rather than a machine-dependent
code-page provider. The generator pins the table digest; a test checks the actual
Python digest for every single-byte and two-byte input (65,792 combinations).
Names also test byte-length prefixes, embedded NUL, invalid pairs, internal
controls, Python-specific whitespace and original-byte preservation.

No official Eve asset was supplied. Official pinned success, resource activation,
live travel, sessions, UI, network, authentication and server acceptance are not
implemented or claimed by these tests.

Final verification: 936 Eve door tests passed within the 1,102-test focused Release run;
11,247 impacted Catalogs + World.Eve tests then passed, zero skips. The tests use the
existing process-only 3 GiB GC heap cap. Independent source/security review approved;
all generated bytes and hashes reproduced exactly. This is not actual-resource,
full application, platform or live-server acceptance.
