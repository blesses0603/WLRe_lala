# Offline catalog parity

This slice ports the following retained Python behavior into `Lala.Core/Catalogs`:

- `wlre/services/world/itemdata_v1.py`: all `Reader` operations and `parse_itemdata` field decoding, input limits, strict UTF-16 names, ID validation, exact consumption, package-version checks, and independently pinned 1296 extension fields. Unreviewed descriptions are skipped exactly as in Python, rather than interpreted as effects.
- `wlre/services/world/item_stack_rules.py`: `can_overlap` validation and every reviewed rule. Typed `ItemStackInput` replaces a dynamic dictionary; missing arguments and non-integer inputs are unrepresentable, and null/out-of-range inputs are rejected.
- `wlre/services/world/combat_catalog.py`: `SKILL_FIELDS` and `parse_skills`, including all 71 unsigned fields in each 125-byte record, source digest, count/length validation, and duplicate/zero IDs. Field spelling and uninterpreted spare values are retained.

## Trust and ownership

Public parsing checks the same fixed source fingerprints as Python. It does not accept a caller-provided digest, a “trusted” boolean, or a caller-supplied version as a substitute for a digest. ItemData's three legacy package versions, or no version, retain Python's limited structural-decoding behavior. Those rows expose only base name, prices, restrictions, usage, and level; `ReviewedDetails` remains null. Legacy parsing does not establish official source provenance.

1296-only fields, stackability, and optional skill links are populated by the production parser only after the fixed 1296 digest matches. SkillData always requires its fixed reviewed digest. Unknown future sources are rejected, not guessed. Returned rows are immutable values with frozen dictionaries and read-only lists. Public parsers copy bounded caller bytes before hashing, so fingerprint checks and decoding operate on the same owned input.

These are data parsers, not authentication or authorization capabilities. Parsed records do not activate a resource generation, authorize packets, establish ownership, or calculate live purchase totals. No UI, Android, filesystem, transport, downloads, or additional dependencies are introduced. Cancellation is checked before work, after hashing, between binary field reads, and before returning the complete frozen snapshot. Failures and cancellation return no partial catalog and do not modify an existing snapshot. Errors contain fixed labels, never resource text.

## Reproduce

From the repository root:

```sh
python dotnet/Lala.Core.Tests/Catalogs/generate_catalog_vectors.py
dotnet test dotnet/Lala.Core.Tests/Lala.Core.Tests.csproj -c Release
```

`PythonCatalogVectors.cs` is generated by executing the retained Python implementations against synthetic records. Its 46 ItemData cases compare every exposed field, 25 SkillData cases compare every field, and 375 distinct stack cases cover fit/type/time/flag combinations, special IDs, attributes, uses, and invalid ranges. No proprietary bundle bytes, live data, or credentials are fixtures.

Tests additionally cover every truncation offset, maximum record counts and UTF-16 name size, oversized buffers, cancellation between fields, immutable outputs, legacy isolation, unknown versions, and public fingerprint rejection of every synthetic fixture. Python's existing tests patch the reviewed fingerprint for synthetic sources; this generator follows that test-only technique. C# tests call internal layout methods via the test assembly, while separate tests prove public parsers reject those same bytes. There is no public source-verification bypass. Consequently the real reviewed-source success branch is **not** an official-resource acceptance test.

## Remaining gaps

- `CurrentStackRules` runtime facade, catalog generation activation and refresh coordination are not ported here.
- `combat_catalog` name/key indexing, NPC decoding, Lua constants, element matrices, full catalog construction, and verified loader/cache orchestration remain Python.
- `normal_attack_catalog`, Unity TextAsset extraction and official Lua decoding are not included.
- Python diagnostic decorators/checkpoint persistence are not ported; C# currently provides bounded typed failures without persisting input or errors.
- Actual official resource fixtures, end-to-end runtime replacement and platform/server acceptance remain separate gates. No Python module is deleted or marked fully migrated by this slice.
